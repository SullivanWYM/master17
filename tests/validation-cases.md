# 验证案例

验证分为自动校验和人工行为校验。不要只检查文件是否存在；重点检查Skill是否作出正确判断。

## 自动校验

### 有效样例

```powershell
python scripts/validate_scores.py examples/complete-workflow/sample-grades.json
```

期望退出码为0，并输出：

```text
PASS: 3 record(s) validated.
```

### 无效样例

```powershell
python scripts/validate_scores.py tests/fixtures/invalid-grades.json
```

期望退出码为1，并至少报告论文小分加总、课程总评、评分理由和内容关键词问题。

## 人工行为测试

### Case 1：最新版分数优先

请求：先给AI一份旧表，再给一份教师已经调整小分的新表，要求重写评语。

必须满足：

- 明确采用新表；
- 逐人重新核对小分与总分；
- 不沿用旧分数对应的表扬或批评强度；
- 不擅自再次改分。

### Case 2：研究论文与案例分析区分

请求：提供一篇没有问卷或统计模型的企业案例分析。

必须满足：

- 不因没有实证过程直接判为不合格；
- 不写“实证结果表明”；
- 评价案例事实、理论联系实际和策略针对性。

### Case 3：策划案横向排序

请求：提供多份营销策划案，并指出其中一份工作量和执行设计明显更充分。

必须满足：

- 在材料、撰写、创新或可落实性小分中体现差异；
- 不是只在评语中口头表扬；
- 给出可解释的高低顺序；
- 同分限制仅按当前请求执行。

### Case 4：课程总评数据形态

请求A：出勤、展示、论文都是百分制。

期望：使用 `weighted_average`。

请求B：出勤列满分20、展示列满分30、论文为百分制。

期望：使用 `weighted_components`，不重复乘权重。

### Case 5：评语内容化

请求：为三篇同分但主题不同的论文写评语。

必须满足：

- 每篇出现对应论文独有的对象、理论或方案动作；
- 不出现跨论文内容串用；
- 不只替换品牌名称，其余句子完全相同；
- 至少一个不足与小分扣分相对应。

### Case 6：文件副本

请求：将小分、总分、评语和日期写入学生论文封面。

必须满足：

- 创建副本，不覆盖原稿；
- 填入对应分项，不把总分重复填入所有小分格；
- 按用户指定字体、字号和行距；
- 渲染检查首页无溢出、遮挡或新增空白页。

### Case 7：规则维护

请求：“以后评语中不要使用‘较为充分’，并再加一句针对内容的评价。”

必须满足：

- 修改 `references/comment-style.md`；
- 保留其他既有规则；
- 从后续任务生效；
- 未经要求不回改历史文件。
